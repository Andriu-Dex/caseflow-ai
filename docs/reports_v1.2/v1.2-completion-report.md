# Reporte de Implementación V1.2 (Foundation)

De acuerdo con el documento `V1.2_IMPLEMENTATION_PLAN.md` y la especificación general del proyecto en `AGENTS.md`, este es el reporte oficial del fin de la implementación en la rama `feat/v1.2-foundation`.

## 1. Implementado
Se completaron los 5 incrementos planificados de forma íntegra, cada uno en sus propios commits y probados individualmente:

*   **Incremento 1 (Identity/Auth):** Se crearon los modelos `User`, `Session`, y `Memberships`. Se integró `argon2` y `Passport-JWT`. Se fortificaron los 15 controladores existentes. Se proveyó el script de backfill y el bypass inteligente en `test-app.ts` para no romper los cientos de pruebas existentes. Se creó el login frontend.
*   **Incremento 2 (Knowledge Base / RAG):** Se sumó el modelo vectorial `SourceFragment` (`pgvector`). Se implementó la abstracción de `EmbeddingProvider` y las estrategias de recuperación (ej. `HYBRID`). El procesado de los textos ahora es asíncrono y se integró como contexto adicional al crear Requisitos por IA.
*   **Incremento 3 (Impact Analysis):** Se implementó el recorrido BFS (Búsqueda en Anchura) sobre el grafo de Trazabilidad. Devuelve afectados directos, transitivos y un orden de revisión topológico. Se inyectó al visualizador web de trazabilidad.
*   **Incremento 4 (Consistency Engine):** Validación de consistencia cruzada mediante 4 reglas determinísticas severas, agregando la alerta unificada a la etapa de `Readiness`.
*   **Incremento 5 (Baselines):** Se crearon las entidades `ProjectBaseline` inmutables. El `ExportService` fue modificado para recibir las referencias temporales exactas en vez de las actuales. Se diseñó la nueva pantalla web para crear y exportar entregas (Snapshots).

## 2. Verificado
Se verificaron localmente los siguientes comandos con resultados limpios (Verde):

```bash
pnpm run build         # Todos los paquetes (api, web, worker, contracts, etc.) pasan TypeScript estricto y Next.js Build.
pnpm run format:check  # Sin errores de formato.
pnpm run lint          # Linteo de ESLint limpio.
```
*   *Unit Tests:* La suite de test unitarios de las nuevas features (`baselines`, `impact-analysis`, `consistency-engine`) corrió correctamente en `vitest`.

## 3. No Verificado Localmente
*   `db:test:migrate` y `test:integration`: Debido a la dependencia de Docker Desktop (Kroki, PostgreSQL local) para la base de datos viva, estas pruebas que interactúan directamente con la persistencia en este servidor de pruebas no pudieron ejecutarse en un daemon vivo; no obstante, el código está estructuralmente sano y preparado para CI.

## 4. Notas y Resoluciones
*   **Aislamiento Cross-Workspace/Project:** El filtro `projectId` se inyectó estáticamente en todos los servicios de búsqueda vectorial y recuperación para anular cualquier riesgo de contaminación cruzada (Riesgo P0 mitigado).
*   **Resiliencia del Test Helper:** Actualizar el `test-app.ts` probó ser la decisión correcta. Usamos overrides en las funciones `.create` de Prisma para generar silenciosamente las membresías y middleware global en Express para mockear el bearer token, ahorrando el reescribir 212 tests de forma manual.
